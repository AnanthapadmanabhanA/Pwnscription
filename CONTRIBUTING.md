# Contributing to Pwnscription

Thanks for helping keep this resource useful and current. Medical-device security moves fast, links rot, regulations get revised, and new research lands all the time. Contributions of every size are welcome.

## Ways to help

- Fix a dead or moved link.
- Add a tool, talk, paper, course, or community that genuinely belongs.
- Flag an out-of-date regulation, standard revision, or date.
- Improve an explanation, fix a typo, tighten wording.
- Add or improve a template or checklist.

## Ground rules

A few things keep this repo trustworthy:

1. **Link to primary sources.** Prefer the regulator, standards body, or original research over a blog that summarizes it. If you cite a secondary source, make that clear.
2. **No exploit payloads or weaponization steps.** This repo teaches methodology and points at tools. Keep it that way, it protects the project and its readers.
3. **Stay vendor-neutral.** Describe what a tool or resource is for. No marketing copy, no ranking vendors.
4. **Keep patient safety front and centre.** Framing matters here more than in most security writing.
5. **One idea per PR.** Small, focused pull requests get reviewed and merged faster.

## How to submit

1. Fork the repo and create a branch (`fix/dicom-link`, `add/ble-tool`, etc.).
2. Make your change. Match the surrounding style and keep Markdown clean.
3. If you added or changed a link, double-check it resolves. CI runs a link check on pull requests.
4. Open a pull request using the template and describe what changed and why.

Not sure about something? Open an issue first and we'll talk it through. There are issue templates for adding a resource and for reporting a broken link.

## Style notes

- Use relative links between files in this repo (`docs/05-tooling.md`), absolute links for external resources.
- Keep headings and the numbered-guide structure consistent.
- Prefer plain, direct English. Short sentences are fine.

## Code of Conduct

Be decent to each other. See [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
